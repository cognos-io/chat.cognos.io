# Internationalisation (i18n)

Cognos ships in **English, German, French, Spanish, Portuguese and Italian**.
Translation is runtime (no per-locale build) via
[Transloco](https://jsverse.github.io/transloco/). A user can switch language on
the fly; the choice is remembered locally and on their account.

> ⚠️ **Translations are AI-drafted and pending native-speaker review.** They are
> good enough to launch, but every non-English catalog (`de/fr/es/pt/it`) should
> get a human pass. Track this before treating copy as final.

## How it fits together

| Piece                                    | File                                                                            |
| ---------------------------------------- | ------------------------------------------------------------------------------- |
| Supported languages + resolution helpers | `frontend/src/app/i18n/languages.ts`                                            |
| Transloco config + app initializer       | `frontend/src/app/i18n/transloco.providers.ts`                                  |
| Catalog HTTP loader                      | `frontend/src/app/i18n/transloco-loader.ts`                                     |
| Runtime language state + persistence     | `frontend/src/app/services/language.service.ts`                                 |
| Switcher UI (globe menu)                 | `frontend/src/app/components/language-switcher/`                                |
| Translation catalogs                     | `frontend/src/assets/i18n/<code>.json`                                          |
| Account field (plaintext)                | `users.preferred_language` (migration `1760000039_users_preferred_language.go`) |

## Which language is shown?

Resolved in `transloco.providers.ts` before first paint, then refined by
`LanguageService` once authenticated:

1. **`localStorage` (`cognos:lang`)** — an explicit prior choice on this device.
2. **`navigator.languages`** — the browser's preferred languages. This is the
   SPA equivalent of the HTTP `Accept-Language` header (a client-rendered app
   can't read the real header without SSR). `de-CH` → `de`.
3. **`en`** — fallback.

Once signed in, the account's `preferred_language` becomes authoritative and is
mirrored back to `localStorage`, so the language follows the user across devices.
A signed-in user with no saved preference has their current (browser-inferred)
choice captured to the account automatically.

Language is stored **in plaintext** (not in the encrypted preferences blob) on
purpose: it must apply before the vault is unlocked, and be available
server-side for localised emails and the Paddle checkout locale. It is not
sensitive — chat content remains end-to-end encrypted.

## Billing / Paddle

The Paddle checkout overlay is opened with `settings.locale` set to the user's
language (`paddleLocaleFor()`), so the checkout UI matches the app. **Currency
stays CHF** (Swiss identity) — set server-side on the transaction; the buyer can
still switch currency inside the overlay.

## Adding a string

1. Add the key to `frontend/src/assets/i18n/en.json` (the source of truth).
2. Add the translation to all other catalogs (`de/fr/es/pt/it`).
3. Use it in a template with the structural directive:

   ```html
   <section *transloco="let t">
     <h1>{{ t('auth.login.title') }}</h1>
   </section>
   ```

   For interpolation: `t('auth.forgot.sent', { email: value })`.

Missing keys fall back to English (`missingHandler.useFallbackTranslation`), so a
half-finished sweep degrades gracefully rather than showing raw keys.

## Adding a language

1. Add an entry to `APP_LANGUAGES` in `languages.ts` (with its `paddleLocale`).
2. Drop a `frontend/src/assets/i18n/<code>.json` catalog.

## Rollout status

The whole app UI is externalised to Transloco across all 6 languages. Coverage:

- [x] Infrastructure (Transloco, LanguageService, switcher, backend field, Paddle locale)
- [x] Auth pages (login, register, forgot/reset password, verify email, confirm email change)
- [x] Account & settings (profile, data export, email, password, danger zone, settings shell nav,
      data-processing)
- [x] Chat (shell, conversation list, messages, composer, model + persona selectors, icebreakers,
      temporary-message dialog)
- [x] Personas (page + editor)
- [x] Billing (dashboard, pricing, lock/past-due banners, switch-plan modal)
- [x] Shared dialogs (confirm, contact, edit/share conversation, vault password) + public
      conversation page
- [x] Service-level alert/toast strings (`errors.*`)
- **Outstanding:** native-speaker review of all non-English catalogues (de/fr/es/pt/it are
  AI-drafted). Tracked as [OP-015](./open-points.md#operations-and-billing).

### Verified by e2e (Playwright, `frontend/e2e/`)

- `language-switcher.spec.ts` — switch + persist on the auth pages
- `account-language.spec.ts` — switch on /account + PATCH to `preferred_language`
- `chat-language.spec.ts` — chat shell renders in a pre-selected language

### Known gaps (intentional, non-UI)

- The downloadable Emergency Kit text (`buildEmergencyKitText`) stays English (file content, not UI
  chrome).
- Backend-supplied error messages are shown verbatim when present; only the English defaults are
  localised.
- Backend catalogue data (model names/descriptions/ineligibility reasons) is not translated here.
